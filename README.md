## 使用方式

### 第一步：通读

按编号顺序阅读 00 → 12。术语表为基础，01–03 为核心，04–08 为决策与执行，09–12 为风险与配套。

### 第二步：批量回填占位字段

在每份文档末尾的"占位字段汇总"区，列出了该文档需要回填的字段。最常出现的占位符：

- `AII` — 项目正式名称
- `AII` — 代币交易所代码
- `《[占位] T0》` — 主网上线日期
- `《[占位] xxx,xxx,xxx》` — 各类数字（代币总量、抵押要求、时间窗口）

建议在所有文件上做一次 sed 全局替换，例如：
```bash
sed -i 's/《\[占位\] 项目名》/MyChain/g' *.md
sed -i 's/《\[占位\] 代币符号》/MYC/g' *.md
```

### 第三步：分组送审

| 文档 | 审阅人 |
|---|---|
| 01, 02, 03 | CTO + 首席架构师 |
| 04, 06 | 共识工程师 + 协议工程师 |
| 05 | CFO + 经济模型顾问 |
| 07, 10, 12 | 法律顾问 + 合规官 |
| 08 | 项目经理 + 各模块负责人 |
| 09 | 安全负责人 + 外部审计代表 |
| 11 | DevRel + SDK 团队 |

### 第四步：导出为可发布格式

Markdown 转 docx：
```bash
pandoc 01_技术白皮书.md -o 01_技术白皮书.docx
```

Markdown 转 PDF（需安装 wkhtmltopdf 或 LaTeX）：
```bash
pandoc 01_技术白皮书.md -o 01_技术白皮书.pdf --pdf-engine=xelatex \
  -V CJKmainfont="Noto Sans CJK SC"
```

## 文档间一致性

所有文档共享如下基线（详见 `00_术语表.md` 与 `01_技术白皮书.md` §10）：

| 维度 | 设定 |
|---|---|
| 总体架构 | 分层多链：主链 + 多子链 |
| 主链共识 | PoW + V 节点签名（混合） |
| 子链共识 | 可插拔：PoS / PBFT / DPoS / Custom |
| 节点角色 | V 节点（底层）+ SCS 节点（子链） |
| 主链 VM | EVM 完全兼容 |
| 子链 VM | EVM + WASM 双轨 |
| 跨链 | 内部协议 + HTLC + 多签桥 + IBC + (后期)XCM |
| 治理 | 链上投票 + AII DAO理事会 + EVR 应急 |
| 实体 | 新加坡AII DAO + BVI 技术公司 + 香港运营公司 |
| 开发语言 | **Rust 全栈** |
| 代币 | 总量上限 21B（占位）、EIP-1559 销毁、年减半 |

修改任一基线项时，请同步更新所有相关文档以保持一致。
